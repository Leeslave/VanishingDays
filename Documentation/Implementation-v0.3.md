# v0.3 P0 구현 기록

아래는 v0.3 당시의 구현 기록입니다. SP 첫 방송과 군중 구조·최동림 첫 만남은 이후 구현됐으며 현재 상태는 [v0.4 구현 기록](Implementation-v0.4.md)을 참고하세요.

적용일: 2026-10-23. 기준: 사용자가 제공한 `Vanishing_Days_Game_Design_Spec_v0.3_Codex.md` 및 앞서 승인한 이석현 일지 보강 원고.

## 재사용과 변경

- 기존 Prototype 씬, uGUI, 9:16 캔버스, 컨셉아트, 오프닝 13단계·문답·닉네임·한글 IME 브리지를 재사용했습니다. 기록지 #001의 마지막 클릭에서만 본편이 열립니다.
- 본편의 이전 여덟 장소·HP 85·자정마다 고정 소멸·7일 승리·기록 송신기는 v0.3 P0와 충돌하므로 교체했습니다. 현재는 네 장소를 유지하며 HP 0까지 자유 생존합니다. 정확한 소멸 발동식은 P1입니다.
- 기존 JSON 저장 방식을 확장했습니다. 새 버전 파일명을 사용하며 이전 저장 파일은 보존합니다.
- 배후 설정과 후반 반전은 UI/아이템 설명/로그에 노출하지 않습니다.

## P0-A: 시작과 집

오프닝 시작 화면에 난이도 선택을 추가했습니다. 초기 식량과 붕대가 난이도에 따라 달라집니다. 붕대는 쉬움 5 / 보통 3 / 어려움 1개를 집에 지급하며 시작 화면에도 표시합니다. 세 난이도 모두 HP 500/500, 부르스타 1, 라디오 0이며 물·가스는 P0 구간의 조리를 막지 않습니다. 물·가스를 영구 무한 공급이라는 세계관으로 확정한 것은 아닙니다.

집에서 밥·스팸·참치·라면 조리와 식사, 휴식/다음 시간대까지 머무르기, 보관/챙기기, 보안 보강을 할 수 있습니다. 닉네임은 기록자에 사용하고 `ProtagonistScriptName`은 별도 관리합니다. 이름 표시 정책은 추가 확정 전까지 강제 통합하지 않습니다.

HP 기준 최대와 현재 HP, 회복 상한을 분리했습니다. 허기 및 부상이 회복 상한을 낮추고, 음식/휴식의 회복은 상한을 넘지 않습니다. 상한이 이미 현재 HP보다 낮아진 경우 즉시 HP를 줄이지 않는 것은 임시 정책입니다. 경험치 레벨업·기준 최대 HP 성장 행동은 만들지 않았습니다.

## P0-B: 외출과 위험

초기 지도는 집·편의점·빈집(추정)·고등학교만 엽니다. 장소 데이터의 이동/수색 시간과 유한한 물자 풀을 사용하며 집에 둔 물건과 배낭을 구분합니다. 길거리와 건물 안의 낮/밤 확률이 각각 있고, 낮은 두 맥락 모두 밤보다 조우가 잦습니다.

낮 조우는 `순순히 내어준다` / `저항한다`를 선택해야 다음 행동을 할 수 있습니다. 해당 미해결 선택도 저장하므로 재실행으로 사건을 건너뛰지 않습니다. 저항은 도주 성공 또는 피해/부상·손실로 이어집니다. 밤 조우는 전문 약탈꾼에 의한 큰 피해·부상·소지품 손실입니다. 전투 전리품이나 새 NPC는 만들지 않았습니다.

집 약탈은 외출의 귀가 시점에 판정하며 보관 물품에만 영향을 줍니다. 보안 성능과 외부 주목도를 분리했습니다. 임시 디지털 보강은 성능이 높아도 주목도 때문에 아날로그 보강보다 위험이 커질 수 있습니다.

옷·무기는 이름/종류를 특정하지 않은 데이터 템플릿입니다. 프로토타입 빈집 물자 풀에 각 1개를 배치해 착용/해제와 힘·방어 보정을 실제로 시험할 수 있게 했습니다. 이 드롭 위치·수량과 보정치는 모두 임시입니다. 착용한 물품은 배낭/창고에서 분리돼 이중 지급되지 않으며, 해제하면 현재 장소에 맞게 돌려줍니다.

## P0-C: 라디오와 서사 게이트

라디오는 학교 수색 진행으로 확정 확보합니다. 확률 실패로 영구히 막히지 않고 중복 지급되지 않습니다. 필수 진행 물품인 라디오와 초기 부르스타는 임시 약탈 대상에서 제외했습니다. 이 보호 정책도 후속 튜닝 대상입니다.

라디오 보유 후 수신 UI가 열립니다. `approvedSPBroadcast`는 승인된 원고가 들어갈 필드이며 현재 비어 있습니다. 따라서 지금은 실제 SP 보도문을 재생하지 않고, 청취 완료 플래그도 허위로 켜지 않습니다. 수신 상태 문구만 표시합니다.

최동림의 첫 만남은 `HasRadio`와 별도의 승인된 군중 구조 조건이 모두 있어야 가능하도록 메서드를 분리했습니다. 현재 일반 플레이에는 그 조건을 참으로 만드는 호출자가 없습니다. 구조 완료는 중복 실행되지 않습니다. 방송 청취를 구조의 추가 필수 조건으로 확정하지 않았습니다. 한지우·해방전선대 합류·이석현 재등장 등도 자동 발생하지 않습니다.

## 검증 및 실행

`Prototype.unity`에서 Play. 저장이 없다면 난이도 선택 및 오프닝으로 시작하고, 저장이 있으면 이어 읽기를 제공합니다. 캔버스 전체는 9:16으로 유지하며 다른 창 비율에는 여백이 생깁니다.

모델 검증: 오프닝 137개 assertion, 생존 94개 assertion 통과. 난이도별 식량·붕대·HP, 약품 치료와 접근/소모/사망/조우 제한, 연속 휴식과 중단/사망, 허기와 부상의 구분, 기존 저장의 약품 풀 보완과 재지급 방지, 회복 상한, 요리/보관, 날짜/조우/보안/장비, 라디오와 서사 게이트, 7일 강제 종료 제거를 검사합니다.

Unity 검증: 실제 리소스 로드, 네이티브 JSON 저장/불러오기, 미해결 조우 복원, 손상 파일의 백업 복구 및 Windows 빌드. UI 검증은 별도 저장 경로에서 진행하며 일반 빌드에 자동 진행/개발 이동 기능을 포함하지 않습니다.

실제 540×960 UI 검증: 난이도 버튼, 오프닝과 한글 입력/IME, 요리·식사 버튼, 창고/배낭, 초기 네 장소, 학교 라디오 획득 및 즉시 인물 등장 차단, 보안 설치, 장비 착용 버튼과 힘/방어 표시, 낮 조우 선택, 회복 상한 450의 막힌 체력바, 전체 세션 저장/로드 통과. 대표 화면은 `SurvivalHomePreview.png`, `SurvivalMapPreview.png`, `SurvivalKitchenPreview.png`, `SurvivalEquipmentPreview.png`, `SurvivalRecoveryCapPreview.png`입니다.

## 보류 항목과 다음 작업

1. SP 첫 방송 원고를 확정해 `approvedSPBroadcast`에 연결.
2. 군중 구조의 독립적인 발생 조건·장소·대사를 확정한 뒤 기존 게이트에 연결.
3. 레시피/음식 효과, 파밍 소진·재생, 장비 종류·드롭, 보안 장치·비용, 허기/부상 회복·상한 중첩 정책을 플레이테스트로 확정.
4. P1: 한지우·요리 특채, 후반 반전, 소멸의 실제 탐색 연계, 엔딩. 날짜나 새 NPC/장소를 임의로 생성하지 않음.
5. 실제 Android/iOS에서 IME 후보창·소프트 키보드·터치 스크롤 확인. 이번 실행 검증은 Windows 9:16 렌더링 기준.

## 약품과 지도 개편 (2026-10-23 추가 요청)

- 시작 붕대 쉬움 5 / 보통 3 / 어려움 1개는 사용자 확정이며, 새 게임의 집 보관함에 한 번 지급합니다.
- 붕대·알약·소독약은 물품 목록 맨 위의 `치료` 버튼으로 사용합니다. 임시 효과는 약품 1개로 부상 1곳 치료 / 1시간 경과입니다. 회복 상한의 부상 감소분을 제거하며 HP를 즉시 채우거나 허기를 없애지 않습니다. 부상이 없거나 접근 가능한 약품이 없으면 물자와 시간을 소모하지 않습니다. 집에 둔 약품은 외출 중 쓸 수 없으며 사망/미해결 조우 중 치료도 차단합니다.
- 집에서 연속 6시간 휴식마다 부상 1곳을 회복합니다. 2시간씩 이어 쉬거나 아침/밤까지 머무르기로 누적합니다. 시간이 드는 다른 행동 또는 새 부상은 진행을 초기화합니다. 지도 보기·보관·장비 정리는 시간을 소모하지 않습니다. 사망한 시간에는 부상 회복을 적용하지 않습니다. 휴식 진행은 저장/로드에 유지됩니다.
- 추가 유한 파밍 풀: 편의점 붕대 1 / 알약 1, 빈집 붕대 2 / 소독약 1, 고등학교 붕대 2 / 알약 2 / 소독약 2. 파밍 수량·약품 효과·치료/휴식 시간은 TEMP_BALANCE이며 JSON에서 조정할 수 있습니다.
- `InjuryRestProgress`와 `MedicalLootVersion`을 기존 v3 JSON에 추가했습니다. 이전 저장에는 누락된 약품 풀만 1회 보완하며 시작 물자를 새로 지급하지 않습니다. 이미 존재하는 소진 스택은 유지하고 재로드로 보충되지 않습니다. Unity 네이티브 JSON에서도 이 호환성과 진행 저장을 검증했습니다.
- `NeighborhoodMapGraphic.cs`는 도로·건물·장소 마커·현재 위치를 uGUI 메시로 그립니다. 실제 지리 좌표를 재현하지 않은 송파구 약도이며 기존 네 장소를 사용합니다. 마커는 위치 정보 화면만 엽니다. 설명·발견 가능 품목·이동/수색 시간·도착 시각을 확인하고 `이동하기`를 눌러야 기존 이동/조우/귀가 판정을 실행합니다. 현재 위치로 이동은 비활성화합니다. 탐색 화면과 하단 귀가 버튼도 위치 정보를 거칩니다.
- 실제 540×960 실행에서 마커 클릭이 위치·시간·난수·외출 상태를 바꾸지 않음, 이동 버튼이 이동 시간을 한 번 적용함, 약품 버튼이 정확히 1개 소비하고 부상을 제거함, 6시간 휴식과 휴식 진행 저장을 확인했습니다 (`VD_MEDICINE_MAP_UI_OK`). Windows 빌드와 모델 94개/오프닝 137개 검증도 통과했습니다.
- 대표 화면: `SurvivalMapPreview.png`, `SurvivalLocationPreview.png`, `SurvivalMedicinePreview.png`. 최신 실행 파일은 `Builds/Windows/VanishingDays.exe`입니다.
## 지도 표시 수정 및 방송 현황 (2026-10-23)

- 장소 이름만 보이는 제보에 대응해 지도 클래스를 `MaskableGraphic`으로 변경하고 `CanvasRenderer` 필수 구성 및 `VertexHelper` 메시 경로를 명시했습니다.
- UI 검증은 이제 Unity가 `VD_UI_VERIFICATION` 심볼로 직접 빌드한 별도 Windows Player를 사용합니다 (`PrototypeBuilder.BuildUIVerification`). 일반 실행 파일에는 해당 자동 진행 코드를 넣지 않습니다.
- 지도 렌더러의 존재·컬링·머티리얼과 도로/건물/마커 메시의 정점·삼각형 개수를 검사합니다. 실제 Windows Player에서 `VD_MAP_RENDER_OK` 및 기존 오프닝/이동/치료 검증을 통과하고 지도 스크린샷을 확인했습니다. 사용자가 제보한 에디터 Play 환경의 수정 후 재현 여부는 별도 확인이 필요합니다.
- 라디오는 획득 및 켜기/청취 연결 지점까지만 구현돼 있습니다. `approvedSPBroadcast`가 빈 문자열이라 현재 실제 방송 이벤트나 음성은 없습니다. 첫 보도문이 기획서에서 미정이어서 새 방송 원고를 임의 추가하지 않았습니다. 라디오 획득으로 최동림이 즉시 등장하지 않는 기존 게이트도 유지합니다.
